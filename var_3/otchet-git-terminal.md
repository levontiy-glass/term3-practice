# Отчёт по заданию: Использование системы контроля версий Git

**Инструмент:** Терминал (Git Bash / Command Line)  
**Вариант:** 4

---

## 1. Выбор инструмента

Выбран терминал (Git Bash), так как это базовый способ работы с Git. Все графические клиенты выполняют те же команды «под капотом». Знание терминала позволяет работать с Git на любой ОС и в любой среде.

---

## 2. Демонстрация основных команд

### 2.1. Создание репозитория

```bash
mkdir my-project
cd my-project
git init
```

**Результат:** создана папка `.git`, репозиторий инициализирован.

---

### 2.2. Клонирование удалённого репозитория

```bash
git clone https://github.com/username/repo.git
```

**Результат:** репозиторий скачан в локальную папку `repo`.

---

### 2.3. Проверка состояния

```bash
git status
```

**Результат:** показано, какие файлы изменены, добавлены или не отслеживаются.

---

### 2.4. Добавление файлов в индекс

```bash
git add index.html
git add .
```

**Результат:** файлы подготовлены к коммиту. `.` добавляет все изменённые файлы.

---

### 2.5. Создание коммита

```bash
git commit -m "Добавлена главная страница"
```

**Результат:** изменения зафиксированы в истории с комментарием.

---

### 2.6. Просмотр истории

```bash
git log --oneline
```

**Результат:** компактный список коммитов (хеш + сообщение).

```
a1b2c3d Добавлена главная страница
e4f5g6h Начальный коммит
```

---

### 2.7. Создание и переключение веток

```bash
git branch feature
git checkout feature
```

Или одной командой:

```bash
git checkout -b feature
```

**Результат:** создана новая ветка `feature` и выполнен переход на неё.

---

### 2.8. Слияние веток

```bash
git checkout main
git merge feature
```

**Результат:** изменения из `feature` влиты в `main`.

---

### 2.9. Отправка и получение изменений

```bash
git push origin main
git pull origin main
```

**Результат:** `push` отправляет локальные коммиты на сервер, `pull` забирает чужие изменения.

---

## 3. Особенности терминала как инструмента

| Особенность | Описание |
|---|---|
| **Универсальность** | Работает на Windows, macOS, Linux |
| **Полный контроль** | Доступны все команды и флаги Git |
| **Скорость** | Нет overhead от графического интерфейса |
| **Автоматизация** | Команды можно объединять в скрипты |
| **Минус** | Нужно помнить синтаксис команд |

---

## 4. Вывод

Терминал — самый гибкий и мощный способ работы с Git. Все основные операции (создание репозитория, коммиты, ветвление, слияние, работа с удалёнными репозиториями) выполняются короткими командами. Графические клиенты удобны для визуализации, но терминал даёт полный контроль и работает везде.
